         TASK SPECIFICATION

         Task Spec / Core Objectives:
         Overview

         For this individual assignment, design and build a Local Feedback Intelligence Assistant. Your
         application will analyse public app-review data with a pretrained Transformers.js model and use a
         lightweight local language model, accessed through Ollama, to propose a bounded follow-up action. A
         person must review the proposal before it can be accepted.

         The coursework assesses WebAI implementation. You may use techniques from the first half of the
         module, but no particular framework, authentication system, or database is required or separately
         marked. You will build the application from the ground up. No starter application is provided.

         Model choice. The recommended baseline is Xenova/all-MiniLM-L6-v2 in Transformers.js and
         gemma3:1b in Ollama. These are not compulsory. Suitable alternatives are welcomed when they meet
         the capability, privacy and reproducibility requirements below. Choosing a larger or less common model
         does not itself earn more marks.

         Description

         Build a web application that helps users explore and triage app reviews.

         Public dataset:

         Use the English classification data from Zero-shot Bilingual App Reviews Mining with Large Language
         Models (Zenodo record 11066414). Select an English file from dataset/for_classification/.

         Core Tasks:

              Import and validate the user feedback data. Show its source, usable row count and clear errors.
              Present feedback in a usable interface that supports selection and inspection.
              Use a Transformers.js-compatible embedding model in the browser to implement one meaningful
              semantic feature. Examples include intent classification, semantic search/ranking, or
              related/duplicate-feedback discovery.
              For selected feedback, send the text and relevant semantic evidence to one lightweight model
              running locally through Ollama.
              Display one closed, structured proposal containing at least an allowlisted action, a short rationale,
              source-evidence reference(s), and a confidence or uncertainty indicator. Validate it locally and
              require an explicit confirm or cancel decision before updating the interface.
              Demonstrate and record test results for the semantic feature and the complete proposal flow,
              including successful, ambiguous and failed cases. Clearly state the desirable features you
              implemented in a single page user guide.

         Model and runtime requirements:

         Bounded-agent requirements:

              Treat imported feedback and model output as untrusted data.
              Restrict proposals to a small documented set of actions and validated arguments. The local model
              may propose only actions defined by the application. It must not call a tool outside the documented
              allowlist.
              Show the proposed action and evidence before a human confirms or cancels it.
              Reject malformed or disallowed output safely and provide a recoverable response when a model or
              service is unavailable.

         P1. Essential Features (50 marks):

         Your application must support a complete flow from importing data to reviewing a proposed action.
         Marks reward correctness, relevance, usability and technical reasoning rather than the use of a
         particular web framework.

              Application and data journey (10 marks)
                Import, validate and display attributed public data through a clear review flow.

              Transformers.js semantic feature (20 marks)
                    Run embedding inference in the browser, use the embeddings for the chosen semantic feature,
                    present interpretable evidence and handle ambiguous results appropriately.

              Bounded local-agent (15 marks)
                    Produce a useful structured proposal, validate its action and arguments, require user
                    confirmation and handle invalid output or unavailable services safely.

              Reliability, usability and code quality (5 marks)
                 Provide clear status and error messages, a usable interface, maintainable code and reproducible
                    setup instructions.

         Minimum requirement. P1 cannot be fully met unless the submission demonstrates both a working
         Transformers.js semantic feature and a locally generated proposal that requires user confirmation.
