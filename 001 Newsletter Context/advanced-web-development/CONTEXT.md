# Mid Module Feedback

Source: https://learn.uea.ac.uk/ultra/courses/_158570_1/announcements/announcement-detail?courseId=_158570_1&announcementId=_534600_1

Published: 2026-11-02T11:25:52.284Z

Hi everyone,

Thank you for submitting your feedback for the Advanced Web Development module. We appreciate you taking the time to share your thoughts. Based on the specific comments raised, here is how we are addressing them:

1. Fast Pacing and Steep Learning Curve: A couple of you noted that the module moves very fast and feels compressed. As highlighted at the start of term, this is the nature of full-stack development: industry-standard frameworks require an intensive pace, backed by substantial self-learning and independent practice outside of class. While demanding, this exposure is designed to give you a solid foundation in the modern workflows and problem-solving skills expected in industry.
2. Lecture Slides and Dense Code: You mentioned that the lectures contain a huge number of slides with dense code, making it difficult to keep up or digest the material. The code shown on the slides was meant to provide you with solutions. Moving forward: We will adjust the lecture structure to focus on the theory and the "why" behind the implementations first, followed by the code. We will slow the pace down and cut down the amount of code directly on the slides, providing the full code as reference files instead.
3. Lectures Running into Lab Time: A comment noted that lectures occasionally run over into lab time. We will stick strictly to the scheduled finish time for the lecture to ensure you have the full lab duration.
4. Lab Sheets ("Do X, Now Do Y") and Working Through Gaps: Feedback mentioned that the lab sheets focus on step-by-step actions without in-depth explanations of every line, and that encountering gaps can leave you stuck. This structure is intentional. In web development, tasks are rarely plain sailing, and learning how to work through ambiguities is an essential practical skill. As advised at the start of the module, you are encouraged to use AI tools when you get stuck to explain concepts, troubleshoot errors, and bridge gaps as part of your active learning process. The teaching team is also on hand during labs to assist when you hit a wall.
5. Readiness for Coursework Projects: Some of you shared that you do not feel ready to start your projects and worry about relying solely on lab code. Bridging lab examples into independent project work requires actively exploring and understanding how the code functions. When you encounter ambiguity or are unsure how to adapt a pattern, be proactive: consult AI tools to break down unfamiliar code, test modifications, and make full use of the ATs available during lab hours to ask questions. Engaging with these resources directly is essential for meeting the learning outcomes and gaining the confidence needed for your coursework.

Thank you again for your time and providing us your feedback, we really appreciate it.

Jeannette and the Teaching Team

   •   Web Programming
       o able to use modern front-end frameworks and browser features to develop

   •   Web Engineering
        o able to design and develop a significant web application that integrates
       front-end and back-end components
   •   Professionalism

Specification

Overview

Build a full-stack, secure Content Management System (CMS) for managing and
publishing newsletters using Next.js (App Router), PostgreSQL with Prisma ORM,
and Auth.js (or custom authentication).


Description

Building a Secure Newsletter CMS. In this assignment, you will build a secure, full-
stack Content Management System (CMS) that allows users to register accounts, log
in, create, draft, schedule, and publish newsletters.
The primary goal of this assignment is to demonstrate a strong authentication system
with solid user session state management. You will design an authorisation
architecture for all users of the system. Public and private facing is core. You must be
able to demonstrate that public routes are for the public while private ones can only
be accessible to eligible users. Security features are the core interests of this
assignment, for example, routes are guarded using Next.js Middleware. We will be
looking closely the solutions you have implemented to cyber defence. These security
features must not be comprising usability features, however. This assignment includes
minimum requirements and desirable requirements. Marks are awarded according to
the quality of your solutions.

Topic Focus: Next.js App Router, PostgreSQL with Prisma ORM, Auth.js / Custom Auth
Systems, Middleware Protection

Technical Stack Requirements
   •   Language: TypeScript
   •   Framework: Next.js
   •   Database & ORM: PostgreSQL + Prisma ORM
   •   Authentication: Auth.js (Credentials or Google OAuth Provider) OR Custom
       Credentials (JWT in HTTP-only cookies)
   •   Styling: Tailwind CSS and DaisyUI

Note: You may be penalised if a tech stack other than listed above is used.

Minimum Technical Requirements (50%):

   1. User Registration
         a User Registration (/register): The application must support new user
            registration. A guest user can create an account with an email,
            password, and optional name.
         b Passwords and its management must be strong and secure.
   2. System Security & Route Guarding
         a. Authentication: Implement authentication using Auth.js or a Custom
            Credentials approach. Logout must also taking care of active session
            cookie, application state, and redirect the user appropriately.
         b. A strong and robust sessions management design architecture
            implemented
         c. End Points: all end points must be secure. The /dashboard route
            and any sub-routes (e.g., /dashboard/create,
            /dashboard/edit/[id]) must be strictly protected. Unauthenticated
            attempts to access /dashboard must not be allowed.
         d. Public Access: whole site apart from dashboard (i.e. no authentication
            required)
         e. Private Access: user dashboard
                   i. The link to /dashboard must only be visible in the navigation
                      bar when a user is authenticated.
        f. Navigation:
                   i. For authenticated users:
                         1. The /login and /register links are hidden
                         2. Their name or email display in the Navbar
                         3. A functional logout button is available for them
                  ii. For public users:
                         1. They can access all public areas of the app.
                         2. /login and /register links are available for them.
  3. Database Schema (Prisma & PostgreSQL)
        a User Model: Stores user credentials (hashed password) or OAuth
            profile details (id, email, name, password, createdAt, updatedAt).
