## Version checks and official references

Checked 5 November 2026. These support implementation details; they do not override the university brief.

- [Next proxy convention/version history](https://nextjs.org/docs/app/api-reference/file-conventions/proxy#version-history): Next16 renames middleware to proxy. Use the file convention matching installed Next. The brief's terminology does not require downgrading.
- [Next authentication: server actions](https://nextjs.org/docs/app/guides/authentication#server-actions): action and data access checks remain necessary even with route guards. Consult this when implementing direct-operation tests.
- [Auth.js Credentials](https://authjs.dev/getting-started/providers/credentials): use the v5-style authorize/provider API taught, not unrelated Better Auth tutorials. The installation page could not be fetched during review; inspect the actual installed package before following imports.
- [Prisma7 migration guide](https://www.prisma.io/docs/guides/upgrade-prisma-orm/v7): check runtime/ESM requirements, generated-client output, driver adapter, root prisma.config.ts and explicit environment loading. Avoid mixing Prisma6 datasource conventions with Prisma7. Lab identifies Prisma7; exact installed patch is not yet known.
- [DaisyUI Next installation](https://daisyui.com/docs/install/nextjs/): matches Tailwind/PostCSS/plugin style used in class. Component HTML is a university-recommended starting resource, not an AI-generated asset; adapt it yourself.

## Evidence review and limitations

All existing context entries were classified: brief/rubric/submission/viva relevant; announcements on individual work, Stugit, DB access and support relevant; repeated submission guidance duplicate; feedback QR and navigation-only folders no implementation content; 002/WebAI and postgraduate report ZIP excluded from this assessment. Generic assessment preparation is an iframe wrapper, not an additional rubric. The fresh module export and nonduplicate Weeks1–5 lectures/labs were inspected; duplicate two-slide files and general Git cheat sheets add no new requirements.

The fresh brief matches the original byte-for-byte. No changed deadline found. Fresh announcement set contained the same 12 announcements. Missing download/extraction reports were empty. Private discussion posts and recorded briefing content were not available through Chalk; no completeness claim about those sources is made.

Specific teaching cautions: Lab4.1 pp18–20 intentionally exposes/stores passwords for demonstration; Lab5 p5 token is unsigned base64; W5 p101 guards on presence and excludes APIs; lab guards block more public pages than this brief allows. W5 p53's claim that cached profile data is completely safe is too broad: cache data is untrusted and name/email still have privacy implications. The recommended design needs no localStorage auth cache. Dummy hash comparison mitigates one timing signal but does not guarantee exactly equal network response times or prevent all enumeration.

Git lab pp13–17 suggests group repositories while the current assessment announcement says individual work: keep your implementation individual. Confirm any required marker access/namespace with the lecturer rather than inventing a group member. The lab's blanket package updater and destructive reset examples are not prerequisites for the assessment.
